## 先看适合哪些场景

| 场景 | 典型流程 | 需要先准备 |
| --- | --- | --- |
| 日常问答、写作与整理 | 选择模型 → 新建会话 → 提问 → 根据回答继续追问 | 至少一个可用的对话模型 |
| 阅读或修改代码 | 绑定项目目录 → 选择“编码” → 先计划或直接构建 → 审核工具操作 | 项目目录、支持工具调用的模型 |
| 查询本地资料 | 添加知识库目录 → 扫描 → 在会话中选择知识库 → 提问 | 本地文档目录；媒体文件扫描另需识别模型 |
| 阅读附件或分析图片 | 添加文件 → 发送问题 → 查看助手引用和处理过程 | PDF/Office 可直接读取；图片、音视频需相应模型能力 |
| 查网页、操作网页 | 配置网络搜索，或安装浏览器扩展 → 提出任务 | 搜索服务密钥或 Chrome/Edge 扩展 |
| 生成图片、视频或音频 | 配媒体模型 → 选应用默认模型 → 在会话里开启能力 → 描述需求 | 对应厂商模型、端点与额度 |
| 批量处理或长期任务 | 先计划 → 设置长任务策略 → 观察待办与工具结果 → 验证交付 | 任务范围、工具权限和时间/额度预算 |
| 复用固定工作流 | 安装 Skill 或配置 MCP → 检查状态与工具 → 在会话中调用 | 完整 Skill 包或可连接的 MCP 服务 |

模型是否支持视觉、推理、工具调用和媒体生成，取决于所选服务商及模型。P-Chat 会显示工具过程，但不能替代服务商本身提供的能力。

## 1. 安装并完成第一次对话

### 下载与启动

从[软件下载页](http://www.08ms.cn/software/p-chat)下载与你的系统匹配的安装包。Windows 运行 `pchat-setup-v*.exe`；Linux、macOS 按下载包中的 `install.sh` 安装。安装完成后从开始菜单、桌面快捷方式或对应应用入口启动 P-Chat。

桌面版会自动启动所需的后端服务，无须另开终端。第一次进入界面时，先配置模型；没有可用提供商时，聊天请求会失败。

### 添加一个 LLM 提供商

1. 点击最左侧导航栏的“设置”，进入“LLM 提供商”，点击“+ 新增”。
2. 选择供应商类型和请求协议，填写 Base URL 与 API Key。使用官方供应商预设时，可先采用自动填入的地址。
3. 添加模型。可以点击“获取模型”查看服务商返回的列表，也可以手动填写模型 ID；检查模型能力和 API 端点后保存。
4. 将常用提供商及对话模型设为默认，点击“测试默认模型”或模型行中的“测试”。
5. 关闭设置，在输入区左下角确认模型名称，发送“你好，请用一句话介绍你自己”。收到流式回复即完成接入。

如果用本地 Ollama，先确认 Ollama 已启动、目标模型已拉取，再按表中地址添加 Custom 提供商；它不需要云端模型额度。若“获取模型”没有返回候选项，可手动填写实际模型 ID，再测试该模型。模型列表能加载不代表聊天接口一定可用，最终以“测试”和实际回复为准。

![当前 LLM 提供商设置页：供应商、协议、Base URL 和模型管理入口](/uploads/202609/02d431a1ee299227.png)

“Base URL”是公共地址，模型的“API 端点”是相对路径。例如 `https://api.openai.com/v1` 加 `/chat/completions` 才形成实际请求地址。选择 Responses 或 Anthropic Messages 协议时，端点分别改为 `/responses` 或 `/messages`。不要把完整聊天接口地址重复填进两处。

| 服务 | 供应商类型 / 请求协议 | 常用 Base URL | 获取密钥 |
| --- | --- | --- | --- |
| OpenAI | OpenAI；按模型选 OpenAI Chat 或 OpenAI Responses | `https://api.openai.com/v1` | [OpenAI API Keys](https://platform.openai.com/api-keys) |
| Anthropic Claude | Anthropic；Anthropic Messages | `https://api.anthropic.com/v1` | [Claude Console](https://console.anthropic.com/settings/keys) |
| DeepSeek | DeepSeek；OpenAI Chat 或其兼容协议 | `https://api.deepseek.com` | [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) |
| 火山方舟 | 火山方舟；按套餐与模型选策略变体、协议 | 普通 API 常用 `https://ark.cn-beijing.volces.com/api/v3` | [火山方舟控制台](https://console.volcengine.com/ark) |
| Ollama | Custom；OpenAI Chat | `http://localhost:11434/v1` | 使用本机 Ollama；模型 ID 取本机已安装模型 |
| 其他兼容服务 | Custom；按厂商文档选协议 | 服务商给出的公共地址 | 服务商控制台 |

各服务商的模型 ID、可用协议、额度和计费会变化，请以服务商控制台为准。火山方舟普通 API、Coding Plan 与 Agent Plan 的地址不同，选错套餐地址可能使请求无法使用预期额度。

服务商文档：[OpenAI](https://platform.openai.com/docs/api-reference/chat/create)、[Claude](https://platform.claude.com/docs/en/api/overview)、[DeepSeek](https://api-docs.deepseek.com/)、[火山方舟](https://www.volcengine.com/docs/82379/1795150)。

![输入区模型选择器：按提供商查找和切换模型](/uploads/202609/83ffb5a0e9b6a5c1.png)

### 手动编辑配置文件（可选）

当前配置文件是 `~/.p-chat/config.json`，不再是旧文章中的 `config.yaml`。你可以在 GUI 中配置，也可以直接编辑 JSON。以下是结构示意，`<模型 ID>` 和 `<API Key>` 必须换成服务商实际提供的值：

```json
{
  "llm": {
    "default": "example",
    "providers": [{
      "name": "example",
      "provider_id": "custom",
      "protocol": "openai_chat",
      "base_url": "https://api.example.com/v1",
      "api_key": "<API Key>",
      "models": [{
        "name": "<模型 ID>",
        "api_endpoint": "/chat/completions",
        "default": true
      }]
    }]
  }
}
```

修改后重新打开设置页或重启应用再测试连接。旧配置会走版本升级流程；不要把含真实密钥的配置文件或截图公开发布。

### 第一次发送消息

点击“新建对话”，在底部输入框键入问题，按 `Enter` 发送；`Shift+Enter` 换行，`Esc` 停止当前生成。点击输入区左下角模型名称可切换本会话模型。

下面是一个最简单的对话示例：发送 `sayHI`，助手返回一句问候。截图来自隔离的本地 mock 会话，仅用于展示界面效果，不使用真实 API Key 或云端模型额度。

![P-Chat 简单对话示例：用户发送 sayHI，助手返回问候](/uploads/202609/b43cb5b95ab0d460.png)

回复中可能出现可折叠的思考、工具调用与子代理卡片。它们展示助手正在做什么、调用是否成功以及耗时。普通问答不一定需要工具。

如果首条消息失败，按“模型测试 → 错误码 → Base URL/模型端点/模型 ID → 账户额度”的顺序排查；修改配置后重新测试，再回到会话重试。不必为一次连接失败重新安装程序。

## 2. 熟悉主界面与会话操作

左侧是项目和会话，中间是消息区与输入区，右侧检查器显示会话操作、项目上下文、模型上下文占用和附件。顶栏可以收起侧栏或检查器；输入区提供模型、会话设置、计划/构建模式和工具权限入口。

点击“会话设置”可分别调整风格、类型、知识库、思考强度、媒体识别、媒体生成、子代理模型与长任务策略。这些选择作用于当前会话；“设置 → 系统”管理应用级默认值。

![当前会话设置：工作类型、风格、知识库、思考和媒体能力](/uploads/202609/8cbbc01fd0113085.png)

| 要做什么 | 操作入口 |
| --- | --- |
| 编程任务或普通工作 | “会话设置 → 类型”选择“编码”或“日常工作” |
| 选择说话方式 | “会话设置 → 风格”；不需要人格时选“关闭” |
| 调整推理强度 | “会话设置 → 思考”；是否生效取决于模型 |
| 先审阅方案 | 输入区“计划”模式；确认方案后切到“构建”执行 |
| 控制工具权限 | 输入区权限按钮；需要确认的操作会弹出提示 |
| 查看工具 | 右侧检查器“工具列表” |
| 查看上下文占用 | 右侧检查器“模型 / 上下文” |
| 查找旧会话 | 左侧搜索框；会话菜单可重命名、归档 |
| 导出会话 | 左侧会话的“更多”菜单选择“导出对话” |
| 重新生成回答 | 助手消息底部“重答”，可在版本切换条查看旧回答 |
| 从某条消息另开路线 | 消息“更多”菜单中的“创建分支对话” |
| 撤回后修改问题 | 用户消息“更多”菜单中的撤回；文字与附件回填输入框 |

会话忙碌时仍可发送下一条消息，P-Chat 会把它放入回合队列；队列支持编辑、删除、失败重试和清空。长任务可以查看待办和子代理进度，再决定是否停止或继续。

### 一次对话从开始到保存

1. 新建会话，选模型，再按任务选择“日常工作”或“编码”；需要资料时先绑定项目、上传附件或选知识库。
2. 发送明确目标和交付形式，例如“比较两份规范，列出差异表并标明依据”。涉及文件修改时，先用“计划”确认范围，再切到“构建”。
3. 观察思考、工具与子代理卡片；出现工具确认时检查命令、路径和影响范围，再决定允许或拒绝。执行过程中可继续输入后续要求，它们会进入队列。
4. 结果不理想时：同一问题换一个回答用“重答”；要改原问题用“撤回”，文字和附件会回到输入框，且可在提示条里撤销此次撤回；要保留原路线另试方案，用“创建分支对话”。
5. 完成后用左侧会话菜单“导出对话”，在弹窗选择 PDF 或 HTML、指定保存路径；暂时不想在列表中看到它，可“归档”。到“设置 → 归档”还能恢复。只有在归档页确认“删除”才是不可撤销的永久删除。

### 长任务和上下文怎么处理

多步骤任务可在“会话设置 → 长任务”选择“关闭 / 自适应 / 不限轮次”。“自适应”适合一般任务；“不限轮次”适合大量资料整理或批量修改，但耗时和模型消耗可能更高。全局的最大回合数、自动压缩缓冲区等在“设置 → 系统”调整。

执行时留意待办、子代理卡片和右侧检查器的上下文占用。若需要停下，按 `Esc` 停止当前生成，再根据已完成的工具结果明确告诉助手“从哪些步骤继续、哪些步骤不要重做”；停止并不等于自动回滚已经执行的文件操作。

排队消息执行失败时，可在队列里重试或删除该项，再检查后续消息是否仍适用。若上下文接近模型上限，可检查模型上下文设置与自动压缩配置；CLI 还提供 `/context` 查看估算、`/compress` 压缩较早历史。

### 让回答保持固定风格

“类型”控制任务侧重点，“风格”控制语气、角色和长期备注，两者不是同一设置。先在“会话设置 → 风格”选内置风格或“关闭”；需要自定义时到“设置 → 风格”点击“+ 新增风格”，填写 Prompt 和记忆并保存，再回当前会话选择它。

例如客服答疑可建一个“温暖简洁”风格：Prompt 写“先给结论，再给必要步骤”，记忆写称呼和表达偏好；保存后在当前会话选中它，发送一条试问，检查回答是否符合预期。不满意时返回风格编辑页调整，再发新消息验证；历史回答不会因为修改风格而自动重写。

![风格列表：内置风格与 mock 自定义风格 warm_demo](/uploads/202609/39939810ff4e88a4.png)

![编辑 mock 风格：显示名称、Prompt 和记忆](/uploads/202609/8bbf0e1d2b2a25b5.png)

如果已有一段满意的对话，也可以点击右侧检查器“生成风格”，从当前对话总结或优化风格。生成后先检查 Prompt 与记忆是否包含不该长期保留的敏感信息；内置风格不可直接修改，可复制为自定义版本。

自动生成的顺序是“完成一段代表性对话 → 点击生成风格 → 选新建或优化已有风格 → 填风格名称和补充要求 → 开始生成 → 审核生成的 Prompt、记忆并保存 → 回到会话选择风格”。下图只填了 mock 名称，未实际调用模型生成。

![从当前 mock 会话生成风格：选择新建或优化已有风格](/uploads/202609/c28bccf0ac2a9b6e.png)

## 3. 绑定项目，让助手理解代码仓库

适合排查报错、理解代码、修改功能和编写测试。一个典型流程是：

1. 点击左上角项目切换器，选择“新建项目”，填写本地项目根目录和名称。
2. 切换到该项目，新建会话；在“会话设置 → 类型”选择“编码”。
3. 对复杂改动先选“计划”，例如提问：“检查登录流程，给我一份最小改动方案和需要验证的测试。”
4. 看完方案后切到“构建”，要求助手实施。读文件、搜索、执行命令和写文件会以工具卡显示；需要确认的步骤由你决定是否继续。
5. 让助手运行相关测试，再查看最终改动、测试结果与未解决的问题。

![项目切换器：全局会话与项目入口](/uploads/202609/96bb341a7559afdf.png)

![新建项目：选择根目录并命名](/uploads/202609/5f5bf679dd36e20e.png)

项目根目录的 `AGENTS.md` 可提供项目约定；项目级配置、规则和 Skill 可补充项目特有能力。项目只是绑定目录，不会在新建时修改项目文件。真正的文件修改发生在后续工具执行阶段。

例如要修复一个测试失败，可描述“复现失败 → 定位相关文件 → 给出最小修复 → 运行对应测试 → 汇报改动与剩余风险”。在“计划”阶段审阅方案；切到“构建”后留意写文件和执行命令的工具卡。工具被拒绝或执行失败时，让助手基于错误调整方案，不要默认它已经修改成功。

## 4. 阅读文件、附件与本地知识库

### 在会话中添加附件

点击输入框旁的附件按钮，或拖入、粘贴文件。源码、文本、PDF、Word、Excel、PowerPoint 等文档可以交由助手按需读取；图片、音频和视频需要模型具备对应输入能力，或在“设置 → 系统 → 媒体识别”配置专门的识别模型。

使用场景示例：“请总结这份 PDF 的三项结论，并标出你实际读到的章节。”附件会先出现在当前会话中，助手需要读取文档内容时再调用读取工具；不支持的文件类型会给出明确提示。

一个稳妥的文件分析流程是“添加附件 → 确认输入区显示文件 → 提出具体问题 → 查看是否出现读取/识别结果 → 核对回答引用的文件内容”。图片、视频、音频若只上传成功却无法理解，优先检查当前会话是否开启对应识别能力，以及识别路由是否有可用模型。

### 建立可重复查询的知识库

如果要反复问同一批文档，可建立知识库：

1. 打开“设置 → 知识库”，启用知识库并新增一个本地目录。
2. 选择要扫描的文件类型和排除规则，点击“扫描”；文本及代码不要求另配向量模型。
3. 若目录包含图片、音频、视频或 PDF 且需要媒体描述，按页面提示配置扫描模型。
4. 回到会话，打开“会话设置 → 知识库”，选择“不使用”“全部知识库”或某一个库。
5. 提问：“比较知识库中两份接口规范的认证差异，并说明来源。”助手会按需检索已扫描内容。

扫描后先看知识库状态与索引条数，再做一次有明确答案的试问。如果检索不到新文件，检查目录、排除模式和扫描错误，再重新扫描；启用“自动扫描”可在启动或路径变更时更新索引。会话选了“不使用”时，即使全局知识库已启用，也不会从该库检索。

![知识库设置：新增本地资料目录并管理索引](/uploads/202609/574649f04fc4f520.png)

知识库使用本地索引和全文检索，适合长期积累的项目文档和笔记；单次上传附件更适合只在当前对话中处理的文件。

## 5. 联网搜索与浏览器操作

### 查公开网页

打开“设置 → 网络搜索”，选择搜索服务、填写密钥，保存并点击“测试连接”。配置成功后，助手可在需要时调用 `web_search`。适合询问最新文档或外部资料；搜索结果仍应核对原始网页。

![网络搜索设置：服务商、配额和连接测试](/uploads/202609/e9b41f138e3a66a8.png)

### 让助手操作已打开的网页

浏览器控制需要 Chrome 或 Edge 扩展，和网络搜索是两项独立能力：

1. 打开“设置 → 浏览器”，启用浏览器控制，下载并解压扩展包。
2. 在 Chrome/Edge 的扩展管理页开启开发者模式，加载解压后的扩展目录。
3. 在扩展弹窗中填写 P-Chat 页面显示的服务器地址，再回到设置页确认“已连接浏览器”大于 0。
4. 浏览器有多个标签页时，先指定“控制目标”。然后提问：“打开这个页面，找到版本号并截图。”

![浏览器设置：扩展安装、连接状态与目标标签页入口](/uploads/202609/0b35eeb032953f7c.png)

助手可以导航、点击、输入、滚动、提取文本和截图。表单输入、上传文件及敏感站点等操作可能触发确认；被禁用的域名会被拦截。截图会作为当前会话的媒体结果显示，能查看和下载。

适合的流程是先指定站点和目标标签页，让助手“提取页面文字并列出证据”，确认定位正确后再要求点击或填写。若希望助手理解截图画面，还需当前模型支持视觉输入，或已配置图片识别路由；仅安装扩展并不能让文本模型看懂截图。

## 6. 图片、视频和音频能力

媒体识别用于理解你上传的图片、音频或视频；媒体生成用于产出新图片、视频或音频。两者要分别配置，并且均受所选模型能力限制。

识别流程：

1. 在“设置 → LLM 提供商”确认模型实际支持对应输入，并正确标记能力；需要独立识别模型时，到“设置 → 系统 → 媒体识别”为图片、视频或音频配置路由。
2. 在当前“会话设置 → 媒体识别”启用所需类型，添加文件并提出具体问题，例如“概括这段录音的决策与待办”。
3. 查看识别过程和回答。若显示不可用，依次检查模型能力、系统路由、会话开关和服务商接口；音频、视频的独立识别还受协议兼容范围限制。

![媒体识别设置入口：按图片、视频、音频分别配置；图中为未启用的 mock 初始状态](/uploads/202609/6a24c50b000fdc65.png)

例如分析产品截图，可先配置支持图片输入的识别模型，再在当前会话打开图片识别、上传截图，并问“指出这张页面里三个最明显的可用性问题”。如果只看到上传成功、却没有视觉分析结果，不要把上传当成识别成功；回到路由和模型能力页检查。

生成流程：

1. 在“设置 → LLM 提供商”点击“+ 添加模型”，将类型设为“媒体生成”，填写模型 ID、勾选它实际支持的操作，并按厂商文档填写创建端点；异步生成还可能需要查询端点。保存后回到提供商模型列表核对能力标签。
2. 到“设置 → 系统 → 媒体生成”，为每项操作选择应用默认模型并保存。当前会话只控制是否启用，不单独覆盖该操作的默认模型。
3. 在“会话设置 → 媒体生成”开启所需能力，输入“根据附件做一张横版封面图”等具体需求；查看生成结果卡，确认内容后下载。若没有结果，检查工具错误、端点、额度及厂商任务状态。

![提供商中分别配置 mock 图片模型 demo-image 与视频模型 demo-video](/uploads/202609/b361d8f17a6f1e52.png)

![应用级媒体生成默认模型：文生图和文生视频分别指向 mock 模型](/uploads/202609/dca5352c557f7e19.png)

![当前会话媒体生成开关：按需启用文生图，其他操作保持关闭](/uploads/202609/630a741b98b295c6.png)

文生图示例：开启“文生图”后，输入“生成一张蓝绿色山峦与日落的横版封面图”。等待 `generate_image` 工具完成，再在结果卡中“查看”大图或“下载”文件。下图画面是本地 mock 返回的演示图片，不是云端模型真实作品。

![mock 文生图结果：图片预览、生成附件和下载入口](/uploads/202609/c693007ead535a19.png)

文生视频示例：为“文生视频”配置默认模型、在会话中开启该能力，再输入“生成一段蓝绿色山峦与日落的短视频”。等待 `generate_video` 工具完成，在结果卡播放或下载。视频可能由厂商异步生成，耗时、文件格式及可用性取决于其接口；下图 WebM 是本地 mock 片段。

![mock 文生视频结果：视频播放器、生成附件和下载入口](/uploads/202609/f1e095508ca074e6.png)

可选操作包括文生图、图生图、文生视频、图生视频、视频生视频以及语音、音乐、音效等。具体选项取决于已经配置的模型与端点。会话未开启的生成能力不会向厂商发起生成请求。

如果想基于已有图片改图，除默认模型和会话开关，还要上传原图并选择支持“图生图”的模型；“图生视频”同理需要参考图片。只配置文生图/文生视频模型，不会自动获得图生图、视频生视频或语音能力。

## 7. Skill、MCP 与 IM 桥接

Skill 是带 `SKILL.md` 的可复用任务说明。使用时先到“设置 → 技能”选仓库、找到 Skill 并安装；确认它出现在“已安装”列表，再在会话中输入 `/` 查看可用命令，或用 `/skill <名称> <任务>` 显式调用。

运行时会显示调用的是哪个 Skill，以及是否就绪。也可将完整 Skill 包放到项目或用户的标准 Skill 目录；只安装同名软件不等于安装了 Skill 包。

想添加自己的工具，可把符合项目格式的 YAML 工具放在用户数据目录的 `tools/` 或项目的 `.p-chat/tools/`。修改后到右侧“工具列表”查看加载情况；解析失败项会出现在加载诊断中。复杂任务可让助手使用子代理拆分工作，执行进度会以嵌套卡片展示。

MCP 设置入口已经提供外部服务管理，当前属于基础可用能力。接入流程是“设置 → MCP → 开启全局开关 → + 添加 → 选择本地 Stdio 或远程 SSE → 填名称及命令/参数/环境变量或 URL → 添加服务器”。

![MCP 设置入口：隔离 mock 环境中尚未添加服务器](/uploads/202609/7a5ac9e6dda240d8.png)

![MCP 添加表单：demo-mcp 与本地演示命令均为未提交的 mock 参数](/uploads/202609/d10cb01d377493cb.png)

列表会显示启动状态、工具数和错误，也可以启停或重启。先确认服务器运行，再到右侧“工具列表”的加载诊断中核对实际可调用的工具；工具暴露、权限与确认体验仍以当前版本为准。不要把未经审查的命令或敏感环境变量交给不可信的 MCP 服务。

“设置 → IM 桥接”提供实验性连接入口。现阶段飞书、微信等通道处于部分可用或持续完善状态，不应把它当成与桌面聊天完全等价的稳定入口。可按“选择通道 → 填写该通道凭据/连接信息 → 启用并检查状态 → 用测试账号发送一条消息 → 核对回复与日志”的顺序验证，正式使用前再检查权限与敏感信息范围。

## 8. 终端 CLI 与独立 Web 模式

安装包除了桌面 GUI，还包含 CLI 与后端服务。Windows 下可在安装目录执行：

```powershell
pchat.exe                 # 进入终端对话；自动启动同目录 server
pchat.exe --provider NAME # 指定已配置的提供商
pchat.exe version         # 查看版本
pchat.exe config          # 查看或管理配置
```

在 CLI 内输入 `/help` 看完整命令。一个常见流程是：用 `/model` 选模型、`/mode coding` 或 `/mode daily` 选类型；复杂任务先用 `/plan <任务>` 审阅方案，执行中用 `/tools` 看可用工具、`/queue` 管理后续消息。

完成后可用 `/export markdown` 或 `/export json` 导出；`/context` 看上下文、`/compress` 压缩较早历史，`/style off` 可关闭风格。GUI 的导出弹窗则提供 PDF/HTML，两端导出格式不要混淆。

如需在浏览器里使用，只启动 `pchat-server.exe`，再打开 `http://127.0.0.1:15150/app/`。该地址适用于默认端口；若服务实际使用其他端口，请以启动输出或配置为准。CLI、GUI 与 Web 模式共用同一个数据目录时，可复用配置与会话。

## 9. 配置、更新与数据位置

当前全局配置为用户目录下的 `~/.p-chat/config.json`，旧版 `config.yaml` 会迁移。项目级配置可放在项目的 `.p-chat/config.json`。会话数据库、知识库索引、上传文件和日志也位于对应的数据目录中。

`PCHAT_HOME` 表示安装目录；`PCHAT_DATA_HOME` 可显式指定数据目录。仓库 `dev-bin/` 启动的开发版默认使用独立数据目录，与正式安装版隔离。排查问题时，日志位于数据目录的 `logs/` 下。

需要检查更新，可从左侧菜单打开“关于 P-Chat”查看当前版本和更新状态。有可安装更新时，按界面提示下载、重启并更新；若只提供外部下载链接，则到[软件下载页](http://www.08ms.cn/software/p-chat)获取对应平台的安装包或更新包。

更新前先导出重要会话，并备份数据目录；升级后再检查模型配置与旧会话是否正常。卸载程序通常保留用户数据，但不应把卸载当作备份。

备份或迁移到另一台电脑时，先让正在运行的任务结束，并完全退出 P-Chat（托盘模式也要退出），再复制整个数据目录。Windows 默认位置是 `%USERPROFILE%\.p-chat`；如果设置过 `PCHAT_DATA_HOME`，以自定义目录为准。备份中可能含 API Key、会话和附件，请勿公开分享。恢复后先测试模型连接，再检查会话和知识库。

桌面版关闭窗口的行为可在“设置 → 系统 → 窗口行为”选择“退出 P-Chat”或“最小化到通知区域”。托盘模式下服务仍会运行；需要完全退出时从托盘菜单退出，避免误以为关窗就结束了后台任务。

## 10. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 首次发送提示没有可用模型或 `E_DISABLED` | 到“设置 → LLM 提供商”添加模型并测试连接，再确认输入区选中的模型。 |
| `401`、密钥无效 | 核对服务商密钥、账户权限和自定义请求头；更新后重试模型测试。 |
| `404` 或模型不存在 | 核对模型 ID，以及 Base URL 与模型 API 端点拼接后的完整地址。 |
| 提示额度不足或 `quota` | 到服务商控制台核对余额、套餐和模型权限；P-Chat 不提供云端模型额度。 |
| 桌面版与 CLI 看到的会话不同 | 检查两者是否使用同一数据目录；开发版 `dev-bin/` 默认与正式版隔离。 |
| 浏览器工具不可用 | 确认浏览器控制已启用、扩展已连接，并检查目标标签页和域名策略。 |
| 媒体识别或生成显示“不可用” | 先配置支持该能力的模型及应用默认值，再到当前会话启用对应能力。 |
| 安装了外部 Skill 却找不到 | 确认已安装完整 `SKILL.md` 包，并在“设置 → 技能”的已安装列表或运行卡片中检查状态。 |
| 回答卡住或失败 | 先看工具卡与错误信息；复制 Trace ID，并检查数据目录 `logs/` 下的日志。 |
| 知识库已经扫描，但回答仍找不到资料 | 检查扫描状态与索引条数、排除规则，并确认当前会话没有选“不使用”；新增文件后重新扫描。 |
| 任务停下后不确定是否完成 | 核对待办、工具卡、文件实际状态和测试结果，再明确要求助手从未完成步骤继续；停止生成不会自动撤销已执行操作。 |
| MCP 已添加却没有工具 | 确认全局开关、服务器运行状态和工具数；查看服务器错误、工具列表及加载诊断。 |
| 关掉窗口后服务还在运行 | 检查“设置 → 系统 → 窗口行为”是否设置为最小化到托盘；需要结束时从托盘退出。 |

如需报告问题，请附 P-Chat 版本、复现步骤、所用协议/模型、错误提示和 Trace ID。请勿公开 API Key 或含敏感内容的日志。
